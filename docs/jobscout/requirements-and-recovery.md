这是项目复盘后的第二阶段，基于 `65f035b1`，对应原方案的“完善要求对照、证据呈现、恢复入口”。不改变历史阶段 0–7 的编号。第一阶段的双侧证据、零分和明确冲突拦截继续有效。

## 匹配报告

推荐表先展示核对分组与待补充事项，依据分移到每个岗位详情。排序仍按代码重算的五维分数，不代表匹配概率或录用概率。分组只反映已有校验结果的完整性，不是另一个模型给出的录用结论。

| 判断 | 依据与处理 |
|---|---|
| 有支持 | 得分项通过原有双侧逐字和对应词校验，或明确学历/经验最低门槛得到简历支持；仍需核对具体满足程度 |
| 支持有限 | 岗位要求熟练/精通，简历只表明了解/入门；保留双方已校验原文，但该项仍为 0 分 |
| 明确不满足 | 可直接比较的学历或经验最低门槛冲突；岗位不入推荐，详情保留双方原文 |
| 待确认 | 缺少信息或校验未通过；无效、虚构引文不在说明中重新出现；未知不等于不符合 |

每项展示岗位字段、原文、简历文件、原文和下一步建议。学历与经验对照不额外加分；预计、计划、否定或无法明确解释的资格不当作已经取得。沿用对“优先”、多学历选项、经验区间和上限表述的保守处理。

最多解释本轮实际校验过的 10 个未入推荐岗位，排除重复与未知 ID；这些记录不进入推荐表或“保存并准备”入口。它们不代表完整岗位库的淘汰清单。审计仍只保存数量与原因计数，不保存原文。服务器运行与离线评测复用相同逻辑；评测器从对应岗位详情检查正分，拒绝缺分、错配、零分与越界分数。

本轮没有修改输入计分协议或 `match_contract_version=1`，第一阶段的已校验报告仍可阅读。只有重新生成的报告具有新对照展示；更早无双侧校验标记的旧报告继续要求重新生成。实时、历史、Markdown 下载和打印共用报告正文。

样式资源带版本标识，打印窗口复用页面的同一版本，避免已有登录页面继续使用升级前的 CSS 缓存。

## 投递检查的恢复方式

| 情况 | 页面建议与入口 |
|---|---|
| 需登录 | 在详情中发起单条检查，在招聘网站浏览器完成登录后继续读取 |
| 抓取失败 | 明确说明未完成读取不代表被拒绝，提供重试；不猜测一定是登录或网站变化 |
| 网站首页 / 证据不足 | 核对个人申请页、岗位和原文，可在原记录上修改查询链接，无需重复添加 |
| 官网与邮件冲突 | 保留双方记录，进入招聘邮件核对；不自动选择一方覆盖 |
| 进行中、阶段未明确 | 保留宽泛原文，等明确阶段再检查，不建议反复刷新 |
| 尚未检查 / 已结束 | 首次检查入口 / 不提供终态重试 |

修改链接只发送原记录的 URL PATCH，不访问新网址、不新增申请，也不自动刷新。前后端均验证 HTTP(S) 与无内嵌凭据；请求继续使用认证、CSRF 与所有权校验。保存失败保留输入，可重试；关闭详情、切换记录或账号后，迟到响应不得恢复旧弹窗或覆盖新内容。邮件提供当前展示阶段时，官网的登录/读取失败仍保留自己的恢复提示。

## 验证与边界

回归包含四种判断、逐字出处、未来/否定资格、无效引文、有限的排除详情、实际中间件与评测器一致性，以及恢复按钮、同记录链接修改、失败重试、迟到响应、桌面/手机、历史回放、打印和下载。结果在 [metrics.md](metrics.md) 中记录；fixture、浏览器与模型均使用合成或拦截数据。

要求对照未逐条穷尽完整 JD，不能处理所有语义、学历写法、年限或偏好。城市/到岗日期等独立偏好表、人工反馈记录、批次成本恢复和真实推荐质量评测仍不在本阶段。原方案要求的独立人工复核、50–100 条真实样本与端到端耗时/成本基线仍待运行，不用合成测试通过率替代。
