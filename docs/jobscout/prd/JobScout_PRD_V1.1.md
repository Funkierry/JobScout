# JobScout PRD V1.1：四阶段变更与验收

日期：2026-10-22。本文件补充 [V1.0 基础需求](JobScout_PRD_V1.0.md)，第四阶段实现基线为 `d25d2d71`。旧版 Axure 与 HTML 保持历史评审版本；本补充不声称已经重新导出它们。

## 产品任务与范围

让求职者能从投递事实、证据判断走到可保存的准备行动；发现问题后保留原结果，记录实际复验。四阶段完成的是可验证的功能和工程回归。真实试用、推荐质量及求职成效仍需独立评估。

| 需求编号 | 现有行为 | 验收依据 |
|---|---|---|
| JS-101 状态表达 | 宽泛“进行中”保留为具体阶段未知；计入待核对，无推定阶段时长 | 状态语义专项与历史迁移测试 |
| JS-102 匹配依据 | 对照同岗位 JD 与简历原文，限制重复加分；明确不满足和零分不入榜 | 匹配契约、grader 与报告测试 |
| JS-103 要求对照 | 展示有支持、支持有限、明确不满足、待确认及后续动作 | 桌面、移动端、历史、下载和打印回归 |
| JS-104 恢复流程 | 从详情进入登录重查、失败重试或修改同一记录的查询链接 | 恢复入口与迟到响应隔离测试 |
| JS-105 准备进度 | 当前账号、对话和报告版本下保存勾选与私人笔记；冲突时保留草稿 | 存储与浏览器回归；重读恢复 |
| JS-106 保守的下一步 | 低置信度、未检查或失败的官网面试识别先核对；保留手动阶段、独立邮件、来源冲突和登录优先级 | 第四阶段新增 3 种异常来源测试 |
| JS-107 反馈复验 | 原记录不可覆盖；关联追加实际结果及“尚未复验 / 用户确认通过 / 用户确认仍有问题” | 账号、资源、报告版本校验与重试去重 |
| JS-108 完整历史访问 | 每次最多 50 条，按 ID 读取更早记录；翻页失败保留已读；导出说明已读数量 | 55 条后端游标用例及 53 条浏览器导出 |

## 反馈复验规则

1. 记录类型、问题类型、原结果、实际结果、原因、下次复验条件、处理结果保留为用户输入。反馈不自动成为招聘事实、匹配证据或模型训练数据。
2. 点击“记录复验 #编号”带入原记录上下文。结论为通过或仍有问题时，必须填写实际检查结果；任务完成与复验通过是两个不同字段。
3. 关联只能指向同账号已有反馈，且投递 ID、对话 ID、报告摘要必须一致。跨账号、资源错配或删除后的记录不能引用。删除资源时清理相应关联记录。
4. 新记录带独立编号和时间；原反馈保持不变。同一请求重试不会新增记录，修改过的同请求被拒绝。旧版本缺失的新字段按默认值比较。
5. 历史按编号倒序翻页，新增反馈不会挤占正在读取的旧页。默认先读 50 条，可继续读取；导出不是静默的全量备份，也不是整个账号的原子快照。

## 验收分层

| 层次 | 本轮能证明的内容 | 不能证明的内容 |
|---|---|---|
| 离线规则/存储 | 状态分流、隔离、引用校验、去重、事实不变 | 真实招聘站点准确率 |
| 合成 UI → API → SQLite | 页面操作经生产路由落库，反馈复验/分页/导出和笔记恢复可完成 | 真实登录、模型生成质量、公司站点或邮箱可用性 |
| GitHub Linux CI | 最终提交的测试与部署检查结果 | 真实用户收益 |
| 本地登录态验收 | 重启健康、新界面可访问、既有记录和笔记未被测试污染 | 长期运行稳定性和真实推荐效果 |

实际测试数、平台既有失败与发布结果分别见 [metrics](../metrics.md) 和 [第四阶段验证](../phase4-validation.md)。没有运行的指标不填写推测值。

## 仍待真实验证

5—8 人试用尚未开展，实施前需各自账号和合适的任务授权。每个试用任务记录任务、结果、原始证据和阻塞点，再由独立复核判断完成情况；反馈条数、勾选数、复验通过数均不能替代用户人数或成功率。

岗位推荐接受率需保留有效推荐与实际选择的分母；状态准确率需独立核验标注；端到端耗时与成本需真实运行记录。模型版本、输入材料、数据时点与缺失用量必须明确。这些仍是后续评价任务，不属于本轮合成测试结论。
