# 可靠性改进记录

本轮从复现缺陷开始，回归测试均使用合成页面、模型和账号。

| 问题 | 实现 | 主要验证 |
|---|---|---|
| 较早开始的检查覆盖新结果 | SQLite 写事务内检查 revision、身份和观测时间；状态、历史和通知一起提交 | 较晚结果先写入、身份改回原值后旧结果到达 |
| 多标签页或调度与手动刷新重复 | 同一进程/事件循环共享岗位锁，等待者发现 revision 已变则跳过 | 两个独立服务实例只调用一次模型工作流 |
| 专属研究 Agent 未接入预算 | 每次运行建立共享用量账本；父子研究共享；投递提取与规划共享 | 真实图搭配假模型，超额后不再调用工具/模型 |
| 自己导出的 CSV 不能再导入 | 独立 CSV 编解码，中文/英文列映射，备注与版本标记 | 导出再导入、公式文本保留、浏览器文件选择 |
| 连接和列表查询开销 | 事务结束关闭连接，缓存按路径初始化的 store；目标列表合并查询 | 12 个岗位从 37 次查询降为 3 次，账号隔离保持 |
| 备份缺少恢复入口 | 独立归档模块，恢复只写空卷，拒绝越界路径和特殊文件 | 本地归档往返、拒绝覆盖；Linux 容器恢复演练 |
| 本地通过但 CI 漏项 | 修复配置隔离/路由覆盖/UTF-8 读取；新增 standalone 浏览器门禁 | 上游 unit/lint/blocking-io + JobScout 专项 + 部署 CI |

CSV 对公式形态字段加制表符文本前缀并整体加引号，版本标记帮助导入恢复原值；不同表格软件可能重新解释保存后的内容，修改过的第三方文件应以实际导入结果为准。导入处理的是岗位登记字段，历史检查和通知请通过数据卷备份恢复。

预算基于供应商响应中的用量，无法撤销已经发出的请求。单条投递检查有独立预算，批量刷新不是一个全局费用预算。单进程锁用于减少重复工作，SQLite 事务校验负责防止过期写入；当前部署仍要求一个 Gateway worker。

代码拆分集中在 CSV、预算和归档这三个有清楚边界的模块。后续仍可做：长列表分页、独立拆分前端视图与状态管理、发布带固定版本的预构建镜像。真实站点覆盖率、完整流程耗时与模型成本评测仍按[评测记录](metrics.md)标为待运行，不能用本轮合成测试代替。

验证入口：`backend/scripts/jobscout_offline_tests.py`、`jobscout-web/test_*.py`、`jobscout-web/test_pure.js`；GitHub Actions 会保存每次运行的测试结果和容器日志。
